Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンド実行などを自律的に行います。この作業は開発者のマシンでリアルタイムに進むため、VS Code の Copilot Chat にはツール呼び出しやファイル編集が逐次表示されます。差分をインラインでレビューし、個々の変更を適用または取り消し、追加のプロンプトで会話を調整できます。エディターを離れる必要はありません。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューし、適用します。
- セッション中にエージェントへ指示し、ハイ コントラストに加えてライト モード切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントが、ハイ コントラスト モードを実装しています。作業中、デザイン チームから追加の依頼がありました。既定のテーマが暗すぎる利用者のため、ライト モード切り替えも追加します。新しい会話を始めずに、進行中のセッションに追加の作業を依頼します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集などの各手順が表示されます。各ファイル編集は差分と **Keep** / **Undo** の操作とともに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールして各ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナル コマンドなどが表示されます。
3. エージェントがファイルの編集を提案したら、差分を確認します。
   - 変更を適用するには **Keep** を選択します。
   - 変更を取り消して、エージェントに再度作業させるには **Undo** を選択します。
4. チャット上部の **Files changed** を開き、セッション中にエージェントが変更したファイルを一覧で確認することもできます。

> [!NOTE]
> ターミナル コマンドの実行などで許可が必要な場合、エージェントは一時停止し **Allow** を表示します。内容を確認し、許可してよいコマンドだけ承認してください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。最後に、変更内容をまとめたメッセージが表示されます。

## エージェントにライト モードを依頼する

ハイ コントラスト モードの実装ができたら、同じ会話でライト モードの切り替えも依頼します。同じ Chat セッションを続けることで、エージェントは前の作業、変更したコンポーネント、スタイル方法、local storage の使用方法をコンテキストとして保持できます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送ります。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントが以前の変更を調べ、ライト モードの追加を提案する様子を確認します。
3. ハイ コントラストのときと同じように、新しい編集をレビューし、それぞれ **Keep** または **Undo** を選択します。
4. エージェントの方向性が希望と異なる場合 (たとえば、切り替え UI を意図せずリファクタリングする場合) は、チャット入力欄の隣にある **Stop** で停止し、追加のメッセージで意図を伝えます。

> [!TIP]
> 進行中のセッションへの追加指示は、新しい会話を最初から始めるよりも早く作業できます。たとえば、「Cascading Style Sheets (CSS) を簡潔にして、セレクターの重複ではなく CSS 変数を使う」「3 つ目の切り替えは追加せず、既存の設定パネルにライト モードを統合する」「両方の切り替えにキーボード ショートカットを追加する」などと依頼できます。

## 変更されたファイルを確認する

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが含まれます。
3. 変更されたファイルをいくつか開き、差分を確認します。Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック HTML、local storage による設定の保持など、カスタム エージェントのアクセシビリティ規則が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode で進行中のセッションを監視し、各ファイル編集を確認して適用または取り消し、コンテキストを保ったまま追加プロンプトで作業を拡張しました。

このレッスンでは、次のことを確認しました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を適用または取り消す。
- 追加プロンプトを使って、進行中のセッションを調整する。

次は[次のレッスン][next-lesson]で、アクセシビリティの変更をプル リクエストとして公開し、このラボでローカルのカスタム エージェントが生成した変更をレビューします。
